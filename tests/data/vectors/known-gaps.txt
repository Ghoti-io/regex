# The vectors this library does not answer the way its oracle does.
#
# One line per record: dialect, flags, pattern, subject, category, and why.
# Tab-separated; the pattern and the subject are escaped the way the runner
# escapes them, so that a tab or a newline inside one cannot split the line.
#
# This file is a gate in both directions. A vector that fails and is not
# listed here fails the suite; a vector that is listed here and *passes* fails
# it too, with "remove the entry" - so the list can only shrink by somebody
# noticing, and never grows by accident.
#
# TWO CATEGORIES, because two different things were being recorded the same
# way and counted the same way.
#
#   gap               this library answers differently from a reference that
#                     is right. It stays in the denominator and counts as a
#                     failure. The rates the README publishes are the rates
#                     *without* these: a gap is counted and named, never
#                     counted as a pass.
#
#   reference-defect  the reference is wrong, and the reason says how we know
#                     rather than asserting it. These leave the denominator,
#                     because a wrong expectation is not a question this
#                     library can be scored against.
#
# The second category is a lever that raises the published rate, so it carries
# two rules. The reason must *demonstrate* the defect - a reproduction someone
# else can run, naming the commands and the outputs, or an upstream issue with
# its fix commit - and never merely argue for it. And the excluded count is
# printed beside the rate wherever the rate appears, so a reader who sees 100%
# sees on the same line what it is 100% of. A rate that rises because rows
# left the denominator has to say so.
#
# An unrecognised category is a hard failure rather than a default, and so is
# an entry with no reason. Defaulting to `gap` would silently demote a row;
# defaulting to `reference-defect` would silently raise the score.
#
# Regenerating: run testVectors, which prints the line to add beneath every
# failure it does not recognise. The *category and reason* are written by
# hand. A reason that begins "not yet classified" is one nobody has looked at,
# and is meant to be read as the admission it is.
perl		(((aa){2})+)	aaaaaaaaaa	reference-defect	reference defect, shown by a minimal pair: perl's answer here is selected by the width of the repeated body and not by any rule. At width one all three agree - `((a){2})+` against "aaa" reports group 2 as 1-2 in perl 5.40.1, in pcre2 10.46 and here. Widen the body and only perl moves: `((aa){2})+` against ten a's is 8-10 in perl and 6-8 in both others; `((aaa){2})+` against ten a's is 6-9 against 3-6; `((ab){2})+` against "ababab" is 4-6 against 2-4. Identical shape, one operand wider, and perl switches from the last iteration that completed to the leftover of the one that failed - because the width is what its compiler uses to choose among its repeat opcodes, and those differ in whether they restore a capture offset when an iteration fails. It is not perl's general position either: `(a)b|aa` against "aa" leaves group 1 unset in all three, so ordinary alternation backtracking does undo the write. Excluded rather than counted because the expectation is a fact about which opcode perl picked, not about the language. Fixed by Perl/perl5#24588, "regexec.c - remove unnecessary logical_to_parno[] mapping", merged to blead 2026-07-22 as 8f0cfc33fc3fabc0d491f71b765b0937d245239c: the mapping from a branch reset group's logical number to its real one was applied twice, once in regcomp.c and again in regexec.c, so anything reading such a group by number reads the wrong one. The pinned perl carries it - the issue's own case, perl -e 'print "abb" =~ s{^(?|(a)|(b)) (?|(a)|(b)) ((\\2)*)}{${&}z}xr', prints abzb where 5.36 printed abbz. **Re-checked on 2026-09-25 when the pin moved to 5.44.0: still wrong, all three reproducers, because the fix landed in blead after 5.44 shipped.** So the instruction below has been carried out once and stands for the next raise. These rows are the same root cause without a backreference: perl reports group 1 of `(?|(a)|(b))` against "b" as "b", and then its own conditional reads that group as unset - `^(?|(a)|(b))(?(1)x|y)$` matches "by" and not "bx" - so one interpreter calls the group set and unset within two lines. pcre2 10.46 and this library both take the true arm. pcre2test refuses the *named* spelling outright (error 165, different names for subpatterns of the same number), so it cannot arbitrate the named form and the numeric form above is what settles it. Re-check when tools/corpus/VERSIONS moves the pin past the fix; if the named answer survives a fixed perl it is a rule worth implementing, and if it does not there was never anything here

rust	U	(a*)+b	aab	gap	this library reports group 1 as 1-2 where the crate reports 0-2; the overall match is 0-3 in both. A lazy loop over a lazy body, and the interaction is what makes it: `(a+)+b` under the same `U` agrees at 1-2, and `(a*)+b` without `U` agrees at 0-2, so neither the laziness nor the empty-matching body is enough on its own. The crate finishes with one iteration spanning the whole run and this library with two, the last of them spanning 1-2 - a difference in which thread the Pike VM keeps when a lazy iteration can match empty, not a difference in the dialect. Found by tools/oracle/linear_diff.py at 105,000 rows, where it is the only disagreement; the row is in tests/data/vectors/rust/named.rxt on purpose, so that this list has to name it rather than the corpus quietly not spelling it.
