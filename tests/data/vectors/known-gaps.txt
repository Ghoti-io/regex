# The vectors this library does not answer the way its oracle does.
#
# One line per record: dialect, flags, pattern, subject, category, and why.
# Tab-separated; the pattern and the subject are escaped the way the runner
# escapes them, so that a tab or a newline inside one cannot split the line.
#
# This file is a gate in both directions. A vector that fails and is not
# listed here fails the suite; a vector that is listed here and *passes* fails
# it too, with "remove the entry" - so the list can only shrink by somebody
# noticing, and never grows by accident.
#
# TWO CATEGORIES, because two different things were being recorded the same
# way and counted the same way.
#
#   gap               this library answers differently from a reference that
#                     is right. It stays in the denominator and counts as a
#                     failure. The rates the README publishes are the rates
#                     *without* these: a gap is counted and named, never
#                     counted as a pass.
#
#   reference-defect  the reference is wrong, and the reason says how we know
#                     rather than asserting it. These leave the denominator,
#                     because a wrong expectation is not a question this
#                     library can be scored against.
#
# The second category is a lever that raises the published rate, so it carries
# two rules. The reason must *demonstrate* the defect - a reproduction someone
# else can run, naming the commands and the outputs, or an upstream issue with
# its fix commit - and never merely argue for it. And the excluded count is
# printed beside the rate wherever the rate appears, so a reader who sees 100%
# sees on the same line what it is 100% of. A rate that rises because rows
# left the denominator has to say so.
#
# An unrecognised category is a hard failure rather than a default, and so is
# an entry with no reason. Defaulting to `gap` would silently demote a row;
# defaulting to `reference-defect` would silently raise the score.
#
# Regenerating: run testVectors, which prints the line to add beneath every
# failure it does not recognise. The *category and reason* are written by
# hand. A reason that begins "not yet classified" is one nobody has looked at,
# and is meant to be read as the admission it is.
perl		(((aa){2})+)	aaaaaaaaaa	reference-defect	reference defect, shown by a minimal pair: perl's answer here is selected by the width of the repeated body and not by any rule. At width one all three agree - `((a){2})+` against "aaa" reports group 2 as 1-2 in perl 5.40.1, in pcre2 10.46 and here. Widen the body and only perl moves: `((aa){2})+` against ten a's is 8-10 in perl and 6-8 in both others; `((aaa){2})+` against ten a's is 6-9 against 3-6; `((ab){2})+` against "ababab" is 4-6 against 2-4. Identical shape, one operand wider, and perl switches from the last iteration that completed to the leftover of the one that failed - because the width is what its compiler uses to choose among its repeat opcodes, and those differ in whether they restore a capture offset when an iteration fails. It is not perl's general position either: `(a)b|aa` against "aa" leaves group 1 unset in all three, so ordinary alternation backtracking does undo the write. Excluded rather than counted because the expectation is a fact about which opcode perl picked, not about the language. Reproduce: feed those four patterns to tools/corpus/perl_match.pl and to tools/oracle/pcre2_match and compare the third span

THREE THINGS THIS ENTRY SAID BEFORE 2026-09-26 WERE WRONG, all in the same direction. (1) "perl 5.44 made them operators of the pattern" - 5.40.1 and 5.44.0 give byte-identical answers to the whole probe; what arrived with the pin raise is the CORPUS, since these rows are absent from 5.40.1's re_tests. (2) The qr// evidence - (?^:[aB]c) on 5.40.1 against (?^:[\lAB]c) on 5.44.0 - compared a LITERAL pattern on one perl with an INTERPOLATED variable on the other; both perls answer both ways. (3) "this library implements neither" reads as one feature with a template half, and the template half (PCRE2_SUBSTITUTE_EXTENDED's \U/\L) is a separate implementation in subst.c that no vector asks for - closing the pattern half alone takes the suite to zero known gaps. WHY THE ROW LOOKS THE WAY IT DOES: re_tests has TWO rows per pattern and the importer kept one. The discriminating subject ("ac" here, where [aB]c matches and [lAB]c does not) disagreed with what tools/corpus/perl_match.pl answered and was dropped as a misread row; the surviving subject is the one both readings satisfy. perl_match.pl interpolates the pattern into qr/$pat/, where perl's double-quote pass has already run, so the engine sees \l and passes it through as the letter with "Unrecognized escape \l passed through in regex". That is a second defect and a larger one: it is the reference for all 6,164 perl vectors. SCOPE: perl passes SIXTEEN unrecognized alphabetic escapes through as the letter (\i \j \l \m \q \u \y \F \I \J \L \M \O \T \U \Y), measured across all 52; PCRE2 10.46 refuses every one of them, with a dedicated error 137 naming \F \L \l \N{name} \U \u, and this library refuses all sixteen exactly as PCRE2 does. Reproduce: perl -e 'print qr/[\lAB]c/' gives (?^:[aB]c); perl -e '$p=q([\lAB]c); print qr/$p/' gives (?^:[\lAB]c).
